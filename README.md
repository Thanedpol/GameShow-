# ใบ้จริง...ใบ้หลอก — Playable Demo

Prototype ทดสอบกลไกเกมโชว์ตอบคำถามภาษาไทย ที่ AI เป็นคนสร้างคำใบ้ — และคำใบ้บางชุด
**ถูกออกแบบให้ผิดโดยตั้งใจ** เพื่อทดสอบทักษะการคิดวิเคราะห์ของผู้เล่น

> นี่คือ prototype สำหรับทดสอบกลไกเกม ไม่ใช่ production

---

## เริ่มใช้งาน

```bash
npm install
```

```bash
cp .env.local.example .env.local
```

ใส่ `ANTHROPIC_API_KEY` ลงใน `.env.local` แล้วรัน:

```bash
npm run dev
```

เปิด http://localhost:3000

### ไม่มี API key ก็เล่นได้

ถ้ายังไม่ได้ตั้ง `ANTHROPIC_API_KEY` เกมจะสลับไป **โหมดสำรอง** อัตโนมัติ
สร้างคำใบ้จากสูตรสำเร็จในเครื่อง (มีป้าย "โหมดสำรอง" กำกับใน UI ทุกครั้ง)
กลไกเกมทั้งหมดยังทำงานครบ — เหมาะกับการเดโมโดยไม่เสียโทเคน

### ปรับความเร็ว

โมเดลเริ่มต้นคือ `claude-opus-5` ซึ่งเปิด thinking โดยดีฟอลต์ จึงใช้เวลาสร้างคำใบ้
ราวไม่กี่วินาที (UI หยุดนาฬิกาและโชว์ spinner ระหว่างรอ จึงไม่กระทบความยุติธรรม)
ถ้าต้องการให้ไวขึ้นสำหรับการเดโมสด ตั้งค่าใน `.env.local`:

```
HINT_MODEL=claude-haiku-4-5
```

> **หมายเหตุ dev:** คำขอแรกที่ยิงไป `/api/hint` จะช้ากว่าปกติ (~10 วิ) เพราะ Next.js
> คอมไพล์ route แบบ on-demand ครั้งเดียว หลังจากนั้นจะไวปกติ
> และอย่ารัน `npm run build` ขณะที่ `npm run dev` กำลังทำงาน เพราะใช้โฟลเดอร์ `.next` ร่วมกัน

## Tech stack

- **Next.js 15** (App Router) + **TypeScript** + **Tailwind CSS 3**
- **ไม่มีฐานข้อมูล** — state ทั้งหมดอยู่ใน React Context + `useReducer` ฝั่ง client
  (รีเฟรชหน้าแล้วเกมเริ่มใหม่ ตามที่โจทย์ยอมรับได้)
- **Anthropic SDK** (`@anthropic-ai/sdk`) เรียกจาก Next.js API Route เท่านั้น
  — `ANTHROPIC_API_KEY` อยู่ใน `.env.local` และไม่เคยหลุดไปฝั่ง client

## กติกาที่ implement ไว้

**ลำดับการเล่น** — Warm-Up 4 ข้อ → Push Your Luck 4 ข้อ → AI Duel Final 1 ข้อ
ผลัดกันตอบคนละข้อ (ข้อ 1 ผู้เล่น 1, ข้อ 2 ผู้เล่น 2, ...)

**คะแนนต่อข้อ** (`lib/scoring.ts`)

| สถานการณ์ | ผลลัพธ์ |
| --- | --- |
| ไม่ขอใบ้ + ตอบถูก | +100% ของคะแนนข้อนั้น |
| ไม่ขอใบ้ + ตอบผิด | 0 → เปิดสิทธิ์แย่งตอบ |
| ใบ้ตรง + ตอบถูก | +50% (จ่ายโทเคน 1 ชิ้น → เต็ม 100%) |
| ใบ้ตรง + ตอบผิด | 0 → เปิดสิทธิ์แย่งตอบ |
| ใบ้ลวง + ตอบถูก | +200% |
| ใบ้ลวง + ตอบผิด | −200% → เปิดสิทธิ์แย่งตอบ |
| แย่งตอบถูก (ภายใน 10 วิ) | อีกฝ่ายได้คะแนนเต็มข้อนั้น |
| แย่งตอบผิด / ขอผ่าน | 0 (ไม่ติดลบ) |
| AI Duel Final | ตอบถูก +200%, ตอบผิด 0 |

คะแนนตั้งต้น: Warm-Up 100 · Push Your Luck 200 · Final 300 (×2 = 600)

**โทเคนคำใบ้** — ตอบถูก "ข้อแรกของแต่ละช่วง" ของตัวเองโดยไม่ขอ AI ช่วย → +1 (สูงสุด 3)

**เวลา** — ตอบ 20 วิ · แย่งตอบ 10 วิ · Final 15 วิ

## สถาปัตยกรรมของ `/api/hint`

```
POST /api/hint   { questionId, correctAnswer, hintType: "ตรง" | "ลวง" | "final" }
  → { revealToken, hints: [{ id, text }], source: "claude" | "fallback" }
```

- **`"ตรง"`** — system prompt บังคับให้เป็นเบาะแสที่ตรวจสอบได้จริง ใกล้เคียงคำตอบ
  ห้ามเฉลยตรง ๆ ห้ามพิมพ์ข้อความของตัวเลือกใด ๆ
- **`"ลวง"`** — ประโยคเดียวที่ผสมเบาะแสจริง 1 อย่าง + เบาะแสหลอก 1 อย่าง
  ที่ทำจากเรื่องสมมติไร้พิษภัย
- **`"final"`** — ยิง 3 คำขอพร้อมกันด้วย `Promise.all` (จริง 1 จาก mode "ตรง" +
  หลอก 2 จาก mode "ลวง" คนละมุม) แล้ว **สลับลำดับแบบสุ่ม** ไม่ให้เดาได้จากตำแหน่ง

**ข้อกำหนดด้านความปลอดภัยใน prompt โหมด "ลวง"** — ห้ามสร้างข้อมูลเท็จเกี่ยวกับ
การแพทย์ สุขภาพ ยา กฎหมาย หรือการเงิน/การลงทุน ที่ผู้ฟังอาจนำไปใช้จริงแล้วเสียหาย
ถ้าคำถามอยู่ในหมวดอ่อนไหว ให้ทำส่วนหลอกจาก trivia สมมติแทน (ตำรา/รายการ/เมือง
ที่ไม่มีอยู่จริง) โดยไม่แตะข้อเท็จจริงที่คนนำไปอ้างอิงต่อได้

**Label จริง/หลอกไม่ถูกส่งไปฝั่ง client** ตอนสร้างคำใบ้ — client ได้แค่ `{ id, text }`
ส่วน `truth` / `mode` / `rationale` ถูก **เข้ารหัส AES-256-GCM** ใส่ไว้ใน `revealToken`
ซึ่ง client ถือไว้เฉย ๆ (อ่านไม่ออก และแก้ไม่ได้เพราะมี auth tag) แล้วส่งกลับมาตอนเฉลย:

```
POST /api/reveal   { revealToken }
  → { questionId, hints: [{ id, text, truth, mode, rationale }] }
```

ที่ออกแบบแบบ **stateless** เพราะ serverless (Vercel) แต่ละ request อาจไปคนละ instance
ถ้าเก็บ label ไว้ใน memory ฝั่งเซิร์ฟเวอร์ ตอนเฉลยจะหาไม่เจอแบบสุ่ม ๆ
วิธีนี้จึงไม่ต้องพึ่ง Redis/DB เพิ่ม และไม่มี state ค้างในเซิร์ฟเวอร์เลย

คีย์เข้ารหัสมาจาก `REVEAL_SECRET` ถ้าตั้งไว้ ไม่งั้น derive จาก `ANTHROPIC_API_KEY`
ผ่าน HKDF-SHA256 (ค่าคงที่ทุก instance อยู่แล้ว) — deploy ได้โดยไม่ต้องตั้ง env เพิ่ม
token มีอายุ 1 ชั่วโมง เกินจากนั้นถอดไม่ผ่าน

## คลังคำถาม

`lib/questions.ts` มี 12 ข้อ — 2 ข้อต่อหมวด ใน 6 หมวด
(สแกม / การเงิน / AI / สุขภาพ / ประวัติศาสตร์ / ตรรกะ)
ทุกข้อมีคำตอบเดียวที่ตรวจสอบได้จริง ไม่ใช่คำถามความเห็น

กระจายเป็น warmup 5 / push 5 / final 2 — แต่ละเกมสุ่มมาใช้ warmup 4 + push 4 + final 1
พร้อมสลับลำดับตัวเลือกทุกข้อ จึงเล่นซ้ำได้ไม่ซ้ำเดิม

เปลี่ยนเป็นคลังจริงภายหลังได้โดยแก้ `QUESTION_BANK` ไฟล์เดียว
(ถ้าเพิ่มจำนวนข้อ ให้ปรับตัวเลขใน `drawQuestions()` ด้วย)

## สมมติฐานที่เติมเข้าไปนอกเหนือจากโจทย์

โจทย์ไม่ได้ระบุประเด็นเหล่านี้ จึงเลือกทางที่สมเหตุสมผลที่สุดและแยกไว้ให้แก้ง่าย:

1. **`Question` ต้องมีตัวคำถาม** — type ในโจทย์ไม่มีฟิลด์ข้อความคำถาม จึงเพิ่ม
   `prompt` (บังคับ) และ `explanation` (ไม่บังคับ ใช้ตอนเฉลย)
2. **โทเคนคำใบ้เอาไว้ทำอะไร** — โจทย์บอกวิธี "ได้มา" แต่ไม่ได้บอกวิธี "ใช้"
   จึงกำหนดให้ **จ่าย 1 ชิ้นเพื่อยกเว้นการหัก 50% ของ "ใบ้ตรง"**
   แก้ได้ที่ `scoreForAnswer()` ใน `lib/scoring.ts`
3. **ลำดับผู้ตอบ** — สลับกันข้อเว้นข้อ (`activePlayerFor()`)
4. **หมดเวลา = ตอบผิด** ใช้กติกาเดียวกันทุกประการ รวมถึงโทษ −200% ของ "ใบ้ลวง"
   เพื่อกันไม่ให้ผู้เล่นดึงเวลาหนีโทษ — และเพื่อไม่ให้ latency ของ API มาทำให้เสียเปรียบ
   นาฬิกาจะ **หยุดระหว่างรอคำใบ้** และการันตีเวลาเหลืออย่างน้อย 12 วินาทีหลังคำใบ้มาถึง
   (ถ้าเรียก API ไม่สำเร็จ ระบบจะยกเลิกโหมดคำใบ้นั้นทิ้ง ไม่คิดโทษผู้เล่น)
5. **Final เฉลยเมื่อไร** — เมื่อหมด 15 วินาที **หรือ** เมื่อทั้งคู่ล็อกครบก่อนเวลา
   (คำตอบถูกซ่อนจากกันตลอดอยู่แล้ว จึงยังยุติธรรมและทำให้จังหวะเกมไม่อืด)
6. **แย่งตอบผิดไม่ติดลบ** และไม่มีการแย่งตอบในรอบ Final (ทั้งคู่ตอบพร้อมกันอยู่แล้ว)
7. **ปุ่ม "เชื่อคำใบ้ชุดไหน" ในรอบ Final ไม่บังคับ** — ใช้บันทึกลง `hintHistory`
   เพื่อให้หน้า Debrief อธิบายได้ว่าผู้เล่นเลือกเชื่อชุดไหนและชุดนั้นจริงหรือหลอก

## ข้อจำกัดที่ควรรู้ (ยอมรับได้ในระดับ prototype)

- **`/api/hint` ไม่มี auth** — ใครได้ URL ก็ยิงถล่มเผาเครดิต Claude ได้
  ถ้า deploy สาธารณะควรเปิด Deployment Protection หรือใส่ rate limit ก่อน
- **client ขอเฉลยล่วงหน้าได้** — `revealToken` อยู่ในมือ client ตั้งแต่ตอนได้คำใบ้
  จะยิง `/api/reveal` ดูก่อนตอบก็ได้ (แม้จะอ่าน token เองไม่ออก)
  ถ้าจะใช้แข่งจริงต้องผูกการเฉลยกับ state ฝั่งเซิร์ฟเวอร์
- **คลังคำถามถูก bundle ไปฝั่ง client ด้วย** (เพราะ reducer สุ่มคำถามฝั่ง client)
  แปลว่าเปิด devtools แล้วเห็นเฉลยได้ — ยอมรับได้สำหรับ prototype
  แต่ถ้าจะใช้แข่งจริงต้องย้ายการสุ่มและการตรวจคำตอบไปไว้ฝั่งเซิร์ฟเวอร์ทั้งหมด
- **เกมอยู่บนเครื่องเดียว (hot-seat)** ผู้เล่นสองคนผลัดกันใช้จอเดียวกัน
  ยังไม่มี realtime/multi-device
- state หายเมื่อรีเฟรช (ตามที่โจทย์ระบุว่ายอมรับได้)

## Deploy ขึ้น Vercel

Repo อยู่บน GitHub แล้ว ใช้วิธี import ง่ายที่สุด:

1. vercel.com → **Add New… → Project** → Import repo นี้
2. Framework Preset จะ detect **Next.js** เอง ไม่ต้องแก้ Build Command / Output Directory
3. ใส่ Environment Variables ตามตารางข้างล่าง
4. กด **Deploy**

Vercel แจก 3 environment มาให้เองโดยไม่ต้องตั้งค่าอะไร — push เข้า `main` = Production,
push branch อื่นหรือเปิด PR = Preview, ส่วน Development คือ `vercel dev` ในเครื่อง

| Environment | ตั้ง env var อะไร |
| --- | --- |
| **Production** | `ANTHROPIC_API_KEY` คีย์จริง |
| **Preview** | คีย์แยกอีกใบ + `HINT_MODEL=claude-haiku-4-5` (เร็วกว่า ถูกกว่า) |
| **Development** | ไม่ต้องใส่ใน Vercel — ใช้ `.env.local` ในเครื่องพอ |

**ควรแยกคีย์ Preview** เพราะ `/api/hint` ไม่มี auth ใครได้ URL ก็ยิงเผาเครดิตได้
และควรเปิด **Settings → Deployment Protection → Vercel Authentication** ให้ Preview ด้วย
(มีใน Hobby plan) เพื่อบังคับล็อกอินก่อนเข้า

> `maxDuration = 60` ถูกตั้งไว้แล้วใน `api/hint` และ `api/debrief` เพราะดีฟอลต์ 10 วินาที
> ของ Vercel ไม่พอสำหรับรอบ Final ที่ยิง Claude 3 คำขอพร้อมกัน
