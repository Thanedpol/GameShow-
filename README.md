# ใบ้จริง...ใบ้หลอก — Playable Demo

Prototype ทดสอบกลไกเกมโชว์ตอบคำถามภาษาไทย ที่ AI สร้างกล่องคำใบ้ให้ 4 กล่อง
— และในนั้นมีทั้งของจริงและของปลอมปนกันเสมอ

> นี่คือ prototype สำหรับทดสอบกลไกเกม ไม่ใช่ production

---

## เริ่มใช้งาน

```bash
npm install
```

```bash
cp .env.local.example .env.local
```

ใส่ `ANTHROPIC_API_KEY` ลงใน `.env.local` แล้วรัน:

```bash
npm run dev
```

เปิด http://localhost:3000

### ไม่มี API key ก็เล่นได้

ถ้ายังไม่ได้ตั้ง `ANTHROPIC_API_KEY` เกมจะสลับไป **โหมดสำรอง** อัตโนมัติ —
สร้างคำใบ้และตรวจคำตอบอัตนัยด้วยสูตรในเครื่อง (มีป้าย "โหมดสำรอง" กำกับใน UI)
กลไกทั้งหมดยังทำงานครบ เหมาะกับการเดโมโดยไม่เสียโทเคน

### ปรับความเร็ว

โมเดลเริ่มต้นคือ `claude-opus-5` ถ้าต้องการให้ไวขึ้นสำหรับเดโมสด ตั้งใน `.env.local`:

```
HINT_MODEL=claude-haiku-4-5
```

> อย่ารัน `npm run build` ขณะที่ `npm run dev` ทำงานอยู่ เพราะใช้โฟลเดอร์ `.next` ร่วมกัน

## กติกา

**เวลา** — ข้อละ **60 วินาที** นับรวมเวลาเปิดกล่องคำใบ้ด้วย นาฬิกา **ไม่หยุดพัก**
ไม่ตอบภายในเวลา = **0 คะแนน**

> กล่องคำใบ้ถูก **โหลดล่วงหน้าตั้งแต่ข้อเริ่ม** ในเบื้องหลัง เพื่อให้กดเปิดได้ทันที
> ผู้เล่นจึงไม่เสียเวลาไปกับการรอ API ทั้งที่นาฬิกาเดินอยู่

**กล่องคำใบ้** — ทุกข้อมี **4 กล่อง** ในนั้นมีทั้งใบ้จริงและใบ้หลอก
**อย่างน้อยอย่างละ 1 กล่องเสมอ** (สัดส่วนสุ่มเป็น 1:3, 2:2 หรือ 3:1
ไม่มีทางเป็นจริงล้วนหรือหลอกล้วน) แล้วสลับตำแหน่งก่อนติดป้าย A–D

**คะแนน**

```
คะแนนที่ได้ = คะแนนข้อนั้น × (1 − 0.25 × กล่องที่เปิดและต้องจ่าย) × (คุณภาพคำตอบ ÷ 100)
```

| สถานการณ์ | ผล |
| --- | --- |
| ไม่เปิดกล่องเลย + ตอบถูก | 100% ของคะแนนข้อนั้น |
| เปิด 1 / 2 / 3 / 4 กล่อง | เหลือ 75% / 50% / 25% / **0%** |
| ไม่ตอบ หรือหมดเวลา | **0** (ไม่มีคะแนนติดลบในเกมนี้) |
| แย่งตอบถูก | ได้คะแนนเต็มของข้อนั้น |

คะแนนตั้งต้น: Warm-Up 100 · Push Your Luck 200 · AI Duel Final 300

**โทเคนคำใบ้** — ตอบถูกข้อแรกของแต่ละช่วงโดยไม่เปิดกล่องเลย → +1 (สูงสุด 3)
ใช้ 1 ชิ้นเพื่อเปิดกล่องแรกฟรี (ไม่หัก 25%)

**แย่งตอบ** — ตอบผิดแล้วยังมีเวลาเหลือ ฝ่ายอื่นแย่งตอบได้ใน **เวลาที่เหลือของข้อนั้น**
(ไม่ต่อเวลาเพิ่ม เพื่อไม่ให้เกิน 60 วินาที) ใช้ได้เฉพาะข้อปรนัย

## Tech stack

- **Next.js 15** (App Router) + **TypeScript** + **Tailwind CSS 3** (ธีมโทนเย็น)
- **ไม่มีฐานข้อมูล** — state อยู่ใน React Context + `useReducer` ฝั่ง client
- **Anthropic SDK** เรียกจาก API Route เท่านั้น — `ANTHROPIC_API_KEY` ไม่หลุดไปฝั่ง client

```
app/
  page.tsx                สลับหน้าจอตาม phase: setup → playing → debrief
  api/hint/route.ts       POST สร้างกล่องคำใบ้ 4 กล่อง (คืน revealToken)
  api/reveal/route.ts     POST ถอด revealToken เป็นเฉลย จริง/หลอก + เหตุผล
  api/grade/route.ts      POST ให้ Claude ตรวจคำตอบอัตนัยตาม rubric
  api/debrief/route.ts    POST สรุปว่ากล่องแต่ละกล่องออกแบบแบบนั้นเพราะอะไร
components/
  SetupScreen · QuestionScreen · DebriefScreen · ScoreBoard · TimerRing · SafetyBanner
lib/
  types · questions (คลังคำถาม) · scoring (กติกาคะแนนจุดเดียวจบ)
  gameStore (reducer) · hintEngine (Claude + เข้ารหัส label) · bot · useCountdown
```

## สถาปัตยกรรมคำใบ้

```
POST /api/hint    { questionId }
  → { revealToken, boxes: [{ id, label, text }] × 4, source }

POST /api/reveal  { revealToken }
  → { questionId, boxes: [{ id, label, text, truth, rationale }] × 4 }
```

**Label จริง/หลอกไม่ถูกส่งไปฝั่ง client** — client ได้แค่ `{ id, label, text }`
ส่วน `truth` และ `rationale` ถูก **เข้ารหัส AES-256-GCM** ไว้ใน `revealToken`
ซึ่งอ่านไม่ออกและแก้ไม่ได้ (auth tag) แล้วส่งกลับมาถอดตอนเฉลย

ออกแบบเป็น **stateless** เพราะ serverless แต่ละ request อาจไปคนละ instance
ถ้าเก็บ label ไว้ใน memory ตอนเฉลยจะหาไม่เจอแบบสุ่ม ๆ วิธีนี้จึงไม่ต้องพึ่ง Redis/DB
คีย์มาจาก `REVEAL_SECRET` ถ้าตั้งไว้ ไม่งั้น derive จาก `ANTHROPIC_API_KEY` ด้วย HKDF-SHA256

**ข้อกำหนดความปลอดภัยใน prompt โหมดหลอก** — ห้ามสร้างข้อมูลเท็จด้านการแพทย์
กฎหมาย หรือการเงินที่นำไปใช้จริงแล้วเสียหาย ให้ใช้ trivia สมมติแทน
(ตำรา/รายการ/เมืองที่ไม่มีอยู่จริง) และสำหรับข้อชีวิตจริง/ที่ทำงาน ส่วนหลอกต้องเป็น
"คำแนะนำที่ฟังดูดีแต่ใช้ไม่ได้จริง" ไม่ใช่คำแนะนำที่ทำแล้วเกิดอันตรายร้ายแรง

## Deploy ขึ้น Vercel

1. vercel.com → **Add New… → Project** → Import repo นี้
2. Framework Preset จะ detect **Next.js** เอง ไม่ต้องแก้อะไร
3. ใส่ Environment Variables ตามตาราง แล้วกด **Deploy**

Vercel แจก 3 environment มาให้เองโดยไม่ต้องตั้งค่า — push เข้า `main` = Production,
branch อื่น/PR = Preview, ส่วน Development คือ `vercel dev` ในเครื่อง

| Environment | ตั้งอะไร |
| --- | --- |
| **Production** | `ANTHROPIC_API_KEY` คีย์จริง |
| **Preview** | คีย์แยกอีกใบ + `HINT_MODEL=claude-haiku-4-5` |
| **Development** | ไม่ต้องใส่ใน Vercel — ใช้ `.env.local` พอ |

**ควรแยกคีย์ Preview** เพราะ API route ไม่มี auth และควรเปิด
**Settings → Deployment Protection → Vercel Authentication** ให้ Preview ด้วย

> `maxDuration = 60` ตั้งไว้แล้วใน `api/hint`, `api/grade`, `api/debrief`
> เพราะดีฟอลต์ 10 วินาทีของ Vercel ไม่พอ

## สมมติฐานที่เติมเข้าไปนอกเหนือจากโจทย์

1. **ราคาการเปิดกล่อง** — โจทย์ไม่ได้ระบุ กำหนดเป็นกล่องละ 25%
   แก้ได้ที่ `BOX_COST_RATIO` ใน `lib/scoring.ts` จุดเดียว
2. **ใครตรวจอัตนัย** — ให้ Claude ตรวจตาม rubric เพื่อให้โหมดเล่นคนเดียวใช้ได้ด้วย
3. **ใครให้คะแนนข้อโชว์** — ผู้เล่นฝ่ายอื่นกดดาว 1–5 (เว็บอัดเสียงไม่ได้
   และในเกมโชว์จริงก็มีกรรมการเป็นคนอยู่แล้ว) เล่นคนเดียว = ประเมินตัวเอง
4. **AI Duel Final ไม่ได้ตอบพร้อมกันแล้ว** — เดิมทั้งคู่ล็อกคำตอบพร้อมกัน
   แต่พอรองรับ 4 ผู้เล่น/ทีม และบังคับ 60 วินาทีต่อข้อ จึงเปลี่ยนเป็น
   ข้อสุดท้ายที่คะแนนสูงสุด (300) ในลูปเดียวกัน ถ้าอยากได้แบบตอบพร้อมกันบอกได้
5. **แย่งตอบเฉพาะข้อปรนัย** — ข้ออัตนัย/โชว์แย่งกันในไม่กี่วินาทีไม่สมเหตุสมผล
6. **ไม่มีคะแนนติดลบแล้ว** — กติกาใหม่คือไม่ตอบ = 0 ตามที่ระบุ

## ข้อจำกัดที่ควรรู้

- **กล่องคำใบ้ถูกโหลดมาครบ 4 ใบตั้งแต่ต้นข้อ** (เพื่อไม่ให้กินเวลาในนาฬิกา 60 วินาที)
  เปิด devtools ดู network ก็เห็นข้อความทั้ง 4 กล่องได้ — แต่ **ไม่เห็นว่าอันไหนจริง/หลอก**
  เพราะ label ถูกเข้ารหัส
- **client ขอเฉลยล่วงหน้าได้** — ยิง `/api/reveal` ก่อนตอบก็ได้ ถ้าจะใช้แข่งจริง
  ต้องผูกการเฉลยกับ state ฝั่งเซิร์ฟเวอร์
- **คลังคำถามถูก bundle ไปฝั่ง client** เพราะ reducer สุ่มคำถามฝั่ง client
- **API route ไม่มี auth** — ใครได้ URL ก็ยิงเผาเครดิตได้
- **การเรียก Claude ต่อข้อค่อนข้างเยอะ** — 4 กล่อง = 4 คำขอขนานต่อข้อ และจะยิง
  ตั้งแต่ข้อเริ่มแม้ผู้เล่นจะไม่เปิดกล่องเลย เป็นราคาที่ต้องจ่ายเพื่อให้กดแล้วเปิดทันที
- เกมอยู่บนเครื่องเดียว (hot-seat) · state หายเมื่อรีเฟรช
